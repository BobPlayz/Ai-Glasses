# Glasses device protocol v1

The laptop service is the local compute host. The device never calls an external API.

## Authentication
- Device requests include X-Device-Token, matching the private token generated by setup.
- The token must stay in the local ignored .device-token file and firmware secrets.h.
- Keep the laptop and device on a trusted private network. The initial protocol uses HTTP on LAN, so do not use a public/shared network.

## Endpoints
- POST /api/device/status: periodic device health and privacy state.
- GET /api/device/command: poll for an explicit capture request.
- POST /api/device/capture-result?request_id=...: upload one JPEG for the current request.
- POST /api/device/capture from the dashboard: creates a one-shot request and waits up to 12 seconds for the image.

## Privacy contract
- No image should be captured unless a user submits a visual question.
- Firmware checks the physical switch immediately before camera capture.
- The indicator must be illuminated while the sensor is capturing.
- The server refuses to accept a capture result unless its last device status reports the switch and indicator as active.
- If dashboard permission or the physical switch is disabled while a capture is pending, the server aborts the request and firmware stops the camera driver on its next poll.
- Software status is not proof of electrical isolation. For a stronger physical guarantee, use a properly designed power-gating circuit after hardware review.

## Payload limits
- Maximum image: 8 MiB.
- Device status should update at least every 2 seconds; the server considers it stale after 8 seconds.
- One capture request is active at a time and expires after 12 seconds.
